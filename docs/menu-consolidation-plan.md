## 1. 审计结论概览

当前 15 个分组、76 个菜单项（不含分组）。主要问题：

1. **「对象 + 对象类型」拆成两个平级菜单**：物料 / 物料类型、载具 / 载具类型、设备 / 设备类型 / 设备组。
2. **父子层级平铺**：工厂 / 区域 / 工作中心 三个独立列表，看不到层级关系。
3. **同一配置链路被拆散**：卡控 绑定 / 方案 / 规则 三个菜单，E10 状态模型 / 自动迁移 两个菜单；
   工艺流程 / 工序 / 产品流程 三个菜单。
4. **查询类页面重叠**：批次履历 vs 追溯查询；批次列表 vs 批次作业。
5. **分组过多**：「批次规则」只有 3 项、「设备主数据」与「设备管理」、「产品与物料」与「仓储」边界模糊，
   一级分组 15 个高于常见的 8–10 个。

## 2. 合并建议（按优先级）

优先级：**P1** 高收益、低风险（纯前端组合页签，后端接口不变）；**P2** 需新页面 / 树组件；
**P3** 结构性调整，建议与角色权限梳理一起做。

| 13 | P2 | 批次履历 / 追溯查询 | **批次履历与追溯**（页签：履历时间线 · 正向 / 反向追溯） | 页签 | 输入同为批次号，用户常从履历继续追溯；保留设备 / 物料批追溯入口 |

## 4. 实施要点

- **页签容器组件**：新增通用 `mes-page:tabs`（菜单 component 携带页签列表，各页签复用现有实体页 `mes:<entity>`），
  页签状态写入 URL（`?tab=`），深链接 / 引用跳转（RefLink）定位到对应页签。
- **权限**：页签按原实体权限（`mes.<module>:read`）逐个显隐；整组无权限时隐藏菜单。
- **菜单同步**：被合并的菜单 key 加入 `OBSOLETE_KEYS`（同 Hold 合并做法），旧路径做前端重定向到新页签，
  避免书签 / 通知中的旧链接 404。
- **i18n**：新菜单标题加入 `layout.py`（en|zh|ja）并重新导出 MES 语言包。
- **测试**：每次合并补菜单同步测试（旧 key 被删除）与页签切换的前端测试。
- **顺序建议**：P1（#1–#7，约 1–2 天，纯前端 + 菜单）→ P2 树组件与主从（#8–#13）→ P3 结合角色梳理。
