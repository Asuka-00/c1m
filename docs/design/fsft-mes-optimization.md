# fsft MES 优化清单（v1.0 已确认）

范围：只做 MES 本身的质量与结构。派工(RTD)、SPC、EAP 不在本期，但结构要为后续集成留好接口。

| # | 项目 | 负责 | 依赖 |
|---|------|------|------|
| 1 | 测试基线报告（通过率、覆盖率）+ GitHub Actions CI（pytest、ruff、mypy、前端测试与 i18n 检查）+ 覆盖率门槛 | 测试评审 | 无 |
| 2 | 模块边界：各模块只通过 service 对外，禁止跨模块 import models；拆掉 warehouse→execution 反向依赖；加 import 规则检查 | 后端（架构师定规则） | 1 |
| 3 | 批次状态机集中管理，非法转移一律拒绝；补 lot 模块测试目录 | 后端 + 测试评审出用例 | 1 |
| 4 | 并发测试：并发过站、重复提交、拆合批同时操作 | 测试评审 | 3 |
| 5 | 合批多批次加锁顺序审查（防死锁），统一按 ID 排序加锁 | 后端 | 4 |
| 6 | 列表查询分页与索引审查 | 后端 | 1 |
| 7 | 过站性能基线（P95 < 500ms）压测脚本 | 测试评审 | 6 |
| 8 | 初始迁移（2466 行）整理，后续迁移按模块拆分、规范命名 | 后端 | 2 |
| 9 | 数据库方言隔离：PG 专有类型（JSONB、ARRAY）集中到一层封装，暂不支持其他数据库 | 后端 | 2 |
| 10 | 轻量事件出口（outbox 表，事件含 ID、类型、对象 ID、版本、租户、时间），暂无消费者 | 后端 | 3 |
| 11 | 拆大组件：lot-console（1199 行）、route-flow、lot-start、split-merge，状态逻辑抽到 hook | 前端 | 1 |
| 12 | 统一按钮权限组件/hook，覆盖 Track In/Out、Hold/Release、拆合批等 | 前端 | 无 |
| 13 | 前端测试：lot、equipment 页面单测，过站与 Hold 端到端测试 | 前端 + 测试评审 | 11 |
| 14 | 数据刷新抽象：轮询统一封装成一个数据源 hook，以后换成推送只改一处 | 前端 | 11 |

不在本期：RTD 派工规则、SPC 模块与控制图、FDC 采集、EAP 状态上报/配方校验/远程命令、推送看板。
