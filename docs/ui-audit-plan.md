# 前端 UX 审计与改进计划（ui-audit-plan）

> 审计时间：2026-10-13；范围：全部 77 个菜单页面（zh-CN，admin 账号，运行中的开发环境 :5173）。
> 方法：Playwright 无头截图（`/workspace/screenshots/ui-audit2/`，文件名 `组序-项序-菜单键.png`，`x-*.png` 为表单 / 下拉 / 横向滚动等专项截图）+ 代码阅读（`components/crud/*`、`features/mes/common/*`、各自定义页面）。
> 本文只列问题与建议，**未做任何代码修改**。优先级：**P1** 影响日常作业效率 / 易出错，应优先处理；**P2** 明显改善体验；**P3** 锦上添花。

> 实施状态：✅ 已完成；◐ 部分完成（未做部分见各批说明）；⏭ 跳过（附原因）。

## 一、共性问题与跨页面改进（优先实施，一次改动覆盖 60+ 个通用实体页）

| # | 优先级 | 问题 | 建议 | 理由 |
|---|---|---|---|---|
| C1 ✅ | P1 | 宽表的操作列不固定：批次、设备、产品等列多的表需横向滚动到最右才能看到操作按钮（见 `x-lot-row-end.png`） | 操作列 `sticky right-0`（带阴影分隔）；首列（编码 / 批次号）也固定在左侧 | 操作入口不可见是最常见的“找不到按钮”问题 |
| C2 ✅ | P1 | 引用字段只显示文本，不能跳转：批次→工单→产品→流程、Hold→批次、量测数据→批次、PM→设备等均无快捷链接 | `cellValue` 对 `ref` 类型渲染为链接（打开目标实体详情抽屉或跳转其列表并按 id 过滤）；批次号统一链接到“批次作业”页 | MES 追溯 / 排查依赖对象间快速跳转，目前需复制编号再切菜单搜索 |
| C3 ✅ | P1 | 筛选下拉不可搜索，且引用型筛选只加载前 100 条（`use-mes-filters.ts` `page_size: 100`）；数据量大时选项不全（见 `x-equipment-filter-dropdown.png`） | 筛选改用可搜索的 Combobox（复用 `ref-select.tsx` 的 Command 组件），远程搜索 `q=` 分页加载 | 设备 / 批次 / 工单数量在量产环境为数百到数万，静态 100 条会漏选 |
| C4 ✅ | P1 | 无日期 / 时间范围筛选：Hold 时间、投产时间、卡控记录、量测数据、E10 履历、停机、审计日志、入库确认时间等全部只能翻页 | 规格字段增加 `filter: range`，前端提供“今天 / 本班 / 近 7 天 / 自定义”日期范围筛选，后端支持 `<field>_from/_to` | 日志 / 履历类查询的首要维度就是时间 |
| C5 ✅ | P1 | 时间类默认排序为升序：后端仅 `created_at` 默认降序（`core/spec/query.py`），`e10_history.at`、`downtime.start_at`、`pm_record.done_at` 等默认最旧在前 | 规格增加 `sort_default_desc`（或按字段类型 datetime 默认降序）；日志类一律最新在前 | 用户打开履历页想看的是最近记录 |
| C6 ✅ | P1 | 筛选条过多一字排开：批次 13 个、产品 10 个、卡控绑定 10 个、分批合批规则 9 个下拉（见 `02-05-mes-lot.png`） | 默认只显示 3–4 个常用筛选 + “更多筛选”折叠面板；已生效筛选显示为可删除的 Chip，并提供“重置” | 降低认知负担，常用筛选一眼可见 |
| C7 | P2 | 无列显示 / 隐藏、列宽调整；列多时表格挤压 | DataTable 增加“列设置”（显示 / 顺序，按用户 + 页面持久化到 localStorage） | 不同岗位关注列不同 |
| C8 | P2 | 缺少批量操作：通用实体表无多选（仅“批量释放 Hold”有）；无法批量启用 / 停用、批量删除、批量改状态 | DataTable 支持行多选 + 批量操作栏（启用 / 停用 / 删除 / 导出所选），删除需二次确认并显示数量 | 主数据维护常需批量处理 |
| C9 ◐ | P2 | 导出不一致：MES 实体页有导出 / 导入，平台页（用户、成员、角色、审计以外）、消息中心、Q-Time 监控、WIP / OEE 报表均无导出 | 所有列表与报表提供“导出 Excel（按当前筛选）” | 报表类页面导出是刚需 |
| C10 | P2 | 页面副标题无意义：通用实体页副标题显示模块名（如“批次”页副标题为“工单”、“设备”页为“设备”） | 副标题改为实体说明（i18n `mes.entityDesc.<code>`），或去掉 | 误导、显得未完成 |
| C11 | P2 | 行操作只有图标无文字（批次行的 3 个图标需悬停才知含义），各页图标含义不统一 | 常用操作保留图标 + Tooltip，次要操作收进“⋯”菜单；统一图标语义（详情 / 编辑 / 履历 / 删除） | 可发现性 |
| C12 | P2 | 详情只能通过弹窗查看，且仅有子表的实体有详情；无“详情页 / 抽屉”承载关联信息（如工单下的批次、设备的 PM / 停机 / E10 履历） | 统一右侧详情抽屉：基本信息 + 关联对象 Tab + 操作历史（审计） | 减少跨菜单查找 |
| C13 | P2 | 空状态单调：只显示“无数据”，无引导（如“尚未创建流程，去新建”或清除筛选） | 空状态区分“无数据”和“筛选无结果”，提供主操作按钮 / “清除筛选” | 新租户上手 |
| C14 | P2 | 表单布局：长表单（产品 11 字段、工单、卡控绑定）两列平铺，无分组，必填与可选混排（见 `x-product-form.png`） | 按“基本信息 / 工艺 / 追踪 / 其他”分段；条件必填字段在条件满足时才显示；长表单改抽屉 | 降低录入错误 |
| C15 | P2 | 快捷键 / 扫码：现场作业页（批次作业、投产、入库）不支持扫码枪输入批次号 / 载具号回车直达 | 提供全局“批次 / 载具 / 设备号”快速搜索框（头部，`/` 聚焦），扫码后直接打开对象 | 产线操作员主要输入方式是扫码 |
| C16 | P3 | 筛选 / 排序 / 分页虽在 URL 中，但无“保存视图” | 支持保存常用筛选为个人视图 | 重复查询场景多 |
| C17 | P3 | 数字列未右对齐、无千分位；状态色不统一（徽章 outline 为主，缺少语义色） | 数值列右对齐 + 千分位；状态统一语义色（运行绿、Hold 红、等待灰、预警黄） | 可读性 |
| C18 | P3 | 删除确认文案通用，未提示被引用影响 | 删除前查询引用计数（“被 3 个流程引用，无法删除”）并在确认框中显示 | 减少 409 后才知道 |

## 二、按菜单分组

### 工作台
| 页面 | 优先级 | 问题 / 建议 | 理由 |
|---|---|---|---|
| 仪表盘 ✅ | P1 | 当前为开发者信息（租户、权限码列表，`01-01-dashboard.png`），无业务内容。改为角色化首页：在制批次 / Hold 数 / Q-Time 预警 / 设备状态分布 / 今日产出 / 我的未读通知 / 常用入口 | 首页是使用频率最高的页面 |
| 仪表盘 | P3 | 权限码列表移到“个人设置 → 我的权限” | 对业务用户无意义 |
